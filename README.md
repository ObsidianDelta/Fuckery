### Version integrity (§15.3) — PENDING

§15.3 makes a published digest the authority for whether a copy of the canon is intact. That
authority only exists if the digest was computed from the actual bytes of the actual file.

**No digest is published here yet, deliberately.** An earlier revision of this README carried a
sha256 string that had not been computed from `CANON.md` — the file was not in the repository,
and the string appears in no other record. It has been retracted rather than corrected, because
a digest that fails `sha256sum` does not read as an error; it reads as evidence that the canon
was altered. A wrong integrity anchor is worse than an absent one.

When the canon is uploaded, this block is completed in the same commit, with the digest computed
by running:

```bash
sha256sum CANON.md
wc -c CANON.md    # byte count
wc -l CANON.md    # line count
```

and a copy of the digest recorded outside this README so it can be cross-checked. Until then,
verify a copy of the canon against the author's own, not against this page.

## Provenance discipline

Every claim in the canon is marked, in spirit if not in literal tag, as one of —
**invariant** (axioms), **derived** (definitions, mappings, consequences), **speculative**
(open problems; protected seams), **illustrative** (the snowflake, the MHC mapping, the
compression analogy), or **reasoning trail** (the path of inquiry).

Reasoning trails are first-class content here. The path by which a claim was reached is not
scaffolding to be discarded once the claim stands.

That discipline applies to this README too. The retraction above is left visible rather than
quietly edited out, because concealing it would violate the same section it is enforcing.
